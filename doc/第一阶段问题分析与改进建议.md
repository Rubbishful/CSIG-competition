## 0. 两条对齐声明（本文的前提）

**对齐 1：`doc/初步分析.md` 描述的是「基线模型」的问题。**
该文档第 3~4 节的全部数值（验证集 5 对的退化画像、默认参数推理的 PSNR/SSIM/LPIPS 退步、`delta_rms +4.78`、高频占比 0.01\~0.07 → 0.10\~0.19、case4 偏色 16.87→16.02）都是**官方发布权重 + 默认推理链路**（`upscale=1`、空 prompt、patch 512/stride 256）的表现。它是**要被超越的基线**，不是"我们训练管线坏了"的证据。本文的推论全部以"基线现象"为出发点，而不是把基线现象当成本项目的缺陷。

**对齐 2：论文推荐的训练顺序是「先训 VAE Encoder → 冻结 Encoder → 训主恢复网络」。**
这一点已由论文原文（[arXiv:2507.20590](https://arxiv.org/abs/2507.20590)，Figure 3 与 §3 Methodology）确认：

> (b) The VAE encoder is fine-tuned specifically for **degradation pre-removal**, enhancing robustness against severe image degradation.
> (c) Subsequently, the **degradation-aware encoder and pre-trained decoder** initialize an adversarially-trained image restoration model, where **only the "Restore Network" is optimized** during this stage.

编码器微调目标（论文式 (3) 前的那一条）：

```
L_E = || V_D(V_ER(I_deg)) − V_D(V_ER(I_GT)) ||_2^2
```

其中 `V_ER` 是待微调的 encoder，`V_D` 是**固定**的 decoder。论文还明确：

> During restoration training, we fine-tune only the intermediate U-Net `U` while **keeping the encoder and decoder fixed**.

**本文最重要的结论由此得出**：我们这个仓库**只实现了 (c)**，并且 (c) 使用的 encoder 是**原始 SD2 VAE encoder**，不是论文要求的 degradation-aware encoder。而 `HYPIR_model/sd2_denoise_ae_encoder.pth` 的存在说明**官方包其实交付了 (b) 的产物，我们的推理链路却从未加载它**。

## 1. 事实核查（全部为本机实测，非推测）

### 1.1 训练链路只覆盖论文的 stage (c)

| 论文阶段 | 本仓库对应实现 | 状态 |
|---|---|---|
| (b) encoder 微调（degradation pre-removal） | **无任何代码** | ❌ 缺失 |
| (c) 冻结 encoder/decoder，LoRA 对抗微调 U-Net | `HYPIR/trainer/base.py` + `HYPIR/trainer/sd2.py` | ✅ 已实现 |

- `base.py:123-126` `init_vae`：`AutoencoderKL.from_pretrained(base_model_path, subfolder="vae")` → `.eval().requires_grad_(False)`。
- `base.py:184-196`：优化器参数只来自 `self.G.parameters()` / `self.D.parameters()`。
- `base.py:209-215`：`accelerator.prepare` 只包 `G/D/G_opt/D_opt/dataloader`。
- `base.py:277`：`z_lq = self.vae.encode(lq).latent_dist.sample()`。因 VAE 全冻结，**`z_lq.requires_grad == False`**，梯度不会流回 encoder。
- 推理端同样冻结（`enhancer/base.py:48-51`），且 `SD2Enhancer` 只加载 LoRA（`enhancer/sd2.py:28-35`）。

### 1.2 权重实测

| 文件 | 张量数 | 参数量 | 说明 |
|---|---|---|---|
| `HYPIR_model/HYPIR_sd2.pth` | 514 | **259.47 M** | 257 个模块 × (lora_A, lora_B)，rank 全 256；与 `configs/*.yaml` 的 `lora_modules` **严格对齐**（无缺失/多余） |
| `HYPIR_model/HYPIR_sd2_D.safetensors` | 38 | 13.01 M | 只有 `decoder.*` / `out.*`（骨架 `convnext_xxlarge` 冻结） |
| `HYPIR_model/sd2_denoise_ae_encoder.pth` | 106 | 34.16 M | **代码中零引用**（全仓 grep `denoise`/`ae_encoder` 无命中） |

**`sd2_denoise_ae_encoder.pth` 与本地 SD2 VAE encoder 的关系（逐层比对）**：

| 检查项 | 结果 |
|---|---|
| 拓扑 | `conv_in → down_blocks → mid_block → conv_norm_out → conv_out`，就是 VAE encoder |
| `conv_out.weight` 形状 | `(8, 512, 3, 3)` → 输出 8 通道 = mean + logvar，与 SD2 VAE 一致 |
| 与 `sd2-1-base/vae` encoder 的键对应 | 106 / 106 一一对应（仅 attention 命名差异：命名侧用 `to_k/to_q/to_v/to_out.0`，本地 VAE 文件用 CompVis 风格的 `key/query/value/proj_attn`） |
| 权重值 | **不同**：逐层权重相关系数 中位数 **0.70**（min 0.30 / max 0.97）；差异相对 L2 中位数 **1.46**；且**所有层的权重 std 都比原 encoder 大**（如 `conv_in.weight` std 0.138 vs 0.118） |

"结构完全一致 + 权重高度相关但系统性偏移 + 滤波器幅度普遍变大" 这一指纹，与论文 stage (b)「在原 encoder 基础上做 degradation pre-removal 微调」的产物高度一致；也与用户记忆中"官方包里带了一个降噪编码器"相符。

> ⚠️ 结论强度：**"它就是 `HYPIR_sd2.pth` 配套的那个 encoder" 目前是高置信度假设，尚未被实验证实**（可能对应另一个变体，如 SDXL/其他版本）。§3 阶段 0 给出了一个 30 秒内可判定、不需要跑推理的实验。

| 位置 | 事实 | 潜在影响 |

| `enhancer/base.py:107-125` | VAE 编码按 tile 进行（patch 512 / stride 256），**每个 tile 独立 `latent_dist.sample()`** | 重叠区随机隐噪声不一致 → 接缝 / 高频噪声 |
| `enhancer/base.py:116-135` | 生成器同样 tile 化前向 | tile 边界处的上下文截断 |

### 1.5 训练数据的"退化语义"与官方一致

`HYPIR/dataset/batch_transform.py:276-277`：`stage2_scale=4` + `resize_back=true` → 先 4× 降采样再插值回原尺寸。
即官方 HYPIR-SD2 训练的是**"同尺寸的模糊 → 清晰"**（`stage2_scale` 只影响退化强度），推理时官方示例用 `--upscale 4` 做 SR，而我们赛题是 `upscale=1` 的同尺寸恢复。**训练语义与赛题基本对齐，差异主要在推理侧的 `upscale` 与后处理。**

## 2. 问题分析

严重度：🔴 阻断（不解决则后续工作无效） / 🟠 高（显著影响指标） / 🟡 中（影响效率或可复现性）

### P1 🔴 缺失论文 stage (b)：推理用的是"未经降噪微调"的 encoder

**现象（基线）**：恢复结果相对 LQ 客观指标全面退步（PSNR 28.03→24.53，SSIM 0.79→0.70）；退化构成从"模糊主导"迁移为"**噪声 + 边缘伪影**主导"；`delta_rms` 全为正（均值 +4.78）；重度模糊的 case4 几乎无结构恢复。见 `doc/初步分析.md` §4。

**机制**：论文的立论是——encoder 先做 degradation pre-removal，使 latent 观测 `y = V_ER(I_deg)` 的退化"变简单"（论文原话：*typically exhibits simpler degradation patterns, characterized mainly by smoothing and adding noise, which can be analogous to the effects of directly applying an MSE-based restoration method*）。单步 `t=200` 的分数估计之所以够用，前提正是"latent 里只剩平滑 + 噪声"。

而我们的 `z_lq` 来自**原始 SD2 VAE encoder**：模糊、偏色、噪声、JPEG 伪影会被**原样带进 latent**，且 SD2 的 VAE 是在自然图上训练的，对重度退化输入的编码本身就在分布之外。结果是 `U_θ(y)` 面对的是一个它**没有被训练过的观测分布**——这正好解释"结构没恢复、反而在 latent 里注入高频噪声"的迁移现象。

**证据链**：
1. 论文 Figure 3 明确 (b) 先于 (c)，且 (c) 继承的是 "the previously fine-tuned degradation-removal encoder"。
2. 本仓库无 (b) 的任何实现（§1.1）。
3. `sd2_denoise_ae_encoder.pth` 是官方交付物、代码零引用、指纹与"encoder 微调"吻合（§1.2）。
4. 官方推理入口 `test.py`/`SD2Enhancer` 也没有 encoder 参数——**说明本地移植时丢了这个组件**，而不是模型没这个能力。

**影响**：如果该假设成立，则基线的大量指标损失属于**部署缺陷**而非模型上限；微调主网络只能在"错误的 latent 观测分布"上做补偿，事倍功半。

**判定实验（阶段 0-A，成本极低）**：见 §3.1。

---

### P2 🟠 `wavelet_reconstruction` 在同尺寸恢复下丢弃模型的低频 → 偏色不可纠正

**现象（基线）**：case4 偏色 `cast 16.87 → 16.02`（几乎未纠正）；`doc/初步分析.md` §4 结论 4 明确记录"偏色基本未纠正"。

**机制**：`utils/common.py:69-80`

```python
content_high_freq, _ = wavelet_decomposition(content_feat)   # 模型输出的高频
_, style_low_freq   = wavelet_decomposition(style_feat)      # LQ 的低频
return content_high_freq + style_low_freq
```

**输出 = 模型高频 + LQ 低频**。这个设计对官方 `--upscale 4` 的 SR 任务是正确的（LQ 没有高频，其低频就是色调参考），但赛题是 `upscale=1` 的**同尺寸恢复**：LQ 里什么都有，其低频正是**偏色与整体色调**。于是模型在低频上做出的任何白平衡/去偏色修正，**在流水线最后一步被整块替换回 LQ 的值**。

**影响**：颜色类退化（case4 的 cast≈17 属重度）在现有链路下**理论上不可能被纠正**；这部分的指标上限被结构性地锁死。这是一个**与训练无关、只改推理就能验证**的缺陷。

---

### P3 🟠 `latent_dist.sample()` + tile 化编码 → 重叠区高频噪声 / 接缝

**现象（基线）**：结果高频占比从 LQ 的 0.01\~0.07 涨到 **0.10\~0.19**，画像结构主导变为"噪声 + 边缘伪影"。

**机制**：编码在 `enhancer/base.py:117` 是 tile 化的，patch 512 / stride 256（50% 重叠），**每个 tile 独立调用 `latent_dist.sample()`**，即向 `z_lq` 注入一份与内容无关的随机隐噪声。重叠区两份独立噪声无法融合成一致结果 → 表现为高频颗粒与 tile 边界伪影。训练侧 `trainer/base.py:277` 也用了 `sample()`，但因为训练是整图 512 单块，不存在"tile 间不一致"。

**影响**：既拉低 PSNR/SSIM，又制造"边缘伪影"这一退化成分；同时让推理结果**不可复现**（同一输入两次结果不同）。

---

### P4 🟠 训练参数是"完整训练口径"，且起点已是收敛权重

**现象**：`lr_G/lr_D` 常数、`max_train_steps` 写死 3 万/4 万、无验证、无早停、隐式 `weight_decay=0.01`。

**机制/影响**：
1. **可训参数量级被低估**：LoRA rank=256 + 257 个目标模块 = **259.47 M** 可训参数（≈ UNet 的 30%），这不是"轻量 adapter"。在已收敛的发布权重上继续用 1e-5 常数 LR 跑 3 万步，**遗忘先验**的风险很高。
2. **没有退火就没有"最优步"**：常数 LR 下 loss/指标曲线后期不会收敛到平台，早停缺少稳定判据。
3. **没有验证集 → 无法选点**：只保留最新两个 `checkpoint-*`（`base.py:447-458`），而"最优"往往不在最后。
4. **`weight_decay` 隐式生效**：`AdamW(lr, betas)` 的默认 `wd=1e-2` 会持续收缩已发布 LoRA（每步很小，但数千步累积）。
5. **无法回退**：没有"step 0 基线"，一旦越训越差，没有机制退回原权重。

---

### P5 🟡 配置是 8 GB 本机的妥协，而非 24 GB 云端的最优值

**现象**：`batch_size: 2`，`lr` 按 `sqrt(2/6)` 手工缩放到 6e-6（`configs/sd2_scene_train.yaml:46`）。

**机制/影响**：本机实测为 **RTX 4060 Laptop / 8 GB**，而正式训练计划在云端 24 GB 进行。batch 2 的 GAN 梯度噪声偏大；`lr` 的缩放系数是按 8 GB 场景手算的。两者都需要在云端重新标定（batch 扫描 + 有效 batch 对齐）。

---

### P6 🟡 若干工程性问题（不致命，但会污染结论）

| 问题 | 位置 | 影响 |
|---|---|---|
| `set_epoch` 从未调用 | `scene_degradation_dataset.py:57` vs `base.py:run` | 每个 epoch 退化链完全一致，样本有效多样性低于名义值 |
| 训练口径 ≠ 部署口径 | `trainer/sd2.py:93-102` vs `enhancer/base.py:116-152` | 用训练口径选出的 checkpoint 未必是部署最优（差了 tiling + `wavelet_reconstruction`） |
| checkpoint ≈ 4.3 GB / 个 | `base.py:445-464` | 短程微调被 IO 与磁盘占用拖累 |
| `self.scheduler` 名称已被占用 | `trainer/sd2.py:18` | 新增 LR scheduler 时必须换名 |
| 模型占位符未填 | `configs/sd2_train.yaml:1,11` 等 `TODO` | 误用会直接失败或训练到错误数据 |

## 3. 改进建议

原则：**先用零成本/低成本的实验把"实现缺陷"和"能力上限"分开，再动 GPU 训练预算。** 顺序不可颠倒——如果 P1/P2 成立，直接在旧链路上微调会把缺陷固化进权重。

### 3.1 阶段 0：确认实验（不训练；预计 < 1.5 小时 GPU）

#### 0-A（最高优先）判定 `sd2_denoise_ae_encoder.pth` 是否为缺失组件

**方法**：用论文 `L_E` 的等价形式做**往返重建**测度，在若干真实/合成 512 对上比较两个 encoder：

```
对每对 (I_lq, I_gt):
  vanilla:  r_lq = V_D(V_E_vanilla(I_lq)),  r_gt = V_D(V_E_vanilla(I_gt))
  denoise:  r_lq = V_D(V_E_denoise(I_lq)),  r_gt = V_D(V_E_denoise(I_gt))
测度:
  (1) 去退化效果: PSNR(r_lq, I_gt)            —— 越大越好（denoise 应显著更高）
  (2) 潜空间一致性: ||V_E(I_lq) − V_E(I_gt)||  —— 越小越好
  (3) 保真护栏: PSNR(r_gt, I_gt)              —— 不能明显下降（denoise 不应破坏干净图重建）
```

**判定标准**：

- 若 (1)(2) 明显改善且 (3) 基本不变 → **确认它就是缺失组件**。此时**不需要训练 stage (b)**，直接改推理链路加载它（§3.2 阶段 0-B），并把它纳入权重契约。
- 若 (1)(2) 无改善或 (3) 明显恶化 → 它不是配套 encoder（或属于其他变体）。转入 §3.3 阶段 1，自行按论文实现 stage (b)。
- 加载方式：`denoise` 文件是**新式 diffusers 命名**，可直接 `vae.encoder.load_state_dict(sd, strict=True)`（本地 VAE 文件是 CompVis 旧命名，`from_pretrained` 已由 diffusers 内部转换）。

> 附带收益：(3) 同时检验了"encoder 微调是否退化成信息丢弃"，这对 §3.3 实现 stage (b) 的护栏设计（见下）也是先验。

#### 0-B 推理链路修正的 A/B（在基线权重上跑，5 对验证集，每项约 6 分钟）

按**单一变量**依次验证，全部用 `evaluate_tool paired` 出指标与退化画像：

| 编号 | 变量 | 预期若为缺陷 |
|---|---|---|
| 0-B1 | 加载 0-A 确认的 encoder（`vae_encoder_path`） | 结构恢复、噪声下降 |
| 0-B2 | 绕过 `wavelet_reconstruction`（`wavelet_recon: false`） | 偏色被纠正，`delta_cast` 显著下降 |
| 0-B3 | `latent_dist.sample()` → `.mode()` | 高频噪声/接缝下降，结果可复现 |
| 0-B4 | `patch_size/stride`：512/256 vs 512/512 | 验证接缝假设 |
| 0-B5 | `(model_t, coeff_t)` 小网格：200/200、300/200、200/300、400/400 | 纹理丰富度—保真度权衡（论文 §5.2.3 的旋钮） |

**实现要求**：所有开关**默认保持现状**（`wavelet_recon=True`、`vae_encode='sample'`、无 `vae_encoder_path`），只在显式传入时改变行为——保证不影响既有链路，且可作为长期可复现的调参入口。

**验收标准**：产出一张 "5 对验证集 × 各设置" 的 PSNR/SSIM/LPIPS/delta_cast/hf 对比表，定位出**每个基线症状对应的最小修复集合**。

### 3.2 阶段 1：补齐论文 stage (b)（仅当 0-A 判定需要时）

#### 目标函数（按论文，可加护栏）

论文原式对 `V_ER` 只有一个"两项相等"的约束：

```
L_E = || V_D(V_ER(I_deg)) − V_D(V_ER(I_GT)) ||_2^2        # V_D 冻结
```

**必须注意一个退化解**：该式存在平凡最优 `V_ER(·) ≡ c`（常数映射使 loss=0）。论文正文未描述额外约束，因此工程实现必须自行加护栏，建议：

```
L = || V_D(V_ER(I_deg)) − V_D(V_ER(I_GT)) ||_2^2
  + λ_keep · || V_D(V_ER(I_GT)) − I_GT ||_2^2            # 保干净图重建，防塌缩
```

外加三重隐式正则：**从原始 encoder（或 0-A 确认的 denoise encoder）初始化 + 小 LR + 少步数 + 早停**。

#### 建议的超参（起点，需云端实测标定）

| 项 | 建议 | 说明 |
|---|---|---|
| 初始化 | `sd2_denoise_ae_encoder.pth`（若 0-A 确认）；否则原始 encoder | 站在官方/原点上做域适配 |
| 可训参数 | **仅 `vae.encoder`**（34.16 M），`vae.decoder` 冻结 | 论文明确 decoder fixed |
| 损失 | `L_E + λ_keep·重建`，`λ_keep` 0.1\~1.0 | 防塌缩 |
| `lr` | 1e-5 起步（无 LoRA，全参数微调），warmup 200 | encoder 只有 34 M，可承受比 LoRA 略高的 LR |
| 数据 | 与 stage (c) 相同的退化管线（`configs/degradation_baseline.yaml`，见 §3.3 的域适配） | 保证 (b)(c) 域一致 |
| 步数/早停 | 3000\~8000 步 + 验证早停（监控 `PSNR(V_D(V_ER(I_lq)), I_gt)` 与保真护栏） | 复用手感同 §3.4 |
| 产物 | `HYPIR_model/HYPIR_sd2_encoder.pth`（**独立 artifact**，不混进 LoRA） | 与 decoder 配对使用 |
| 交付 | 推理端新增 `vae_encoder_path`，`SD2Enhancer` 一并加载 | 否则等于没做 |

#### 关键约束（必须写进流程）

> **encoder 是 stage (c) 的"固定输入管线组件"，不是 (c) 的可训参数。**
> 因为 `z_lq = V_ER(I_lq)` 的分布直接决定 U-Net 的输入，**一旦 encoder 变化，此前所有 (c) 的 LoRA 权重全部失效，必须重跑 (c)**。
> 所以：**(b) 只能在 (c) 之前做；(b) 完成后 encoder 必须冻结；(c) 期间不得再动 encoder。**
> 这条同时回答了"VAE encoder 是否在微调范围内"——**不在 stage (c) 的范围内，但必须在 stage (c) 之前被训练或选定。**

### 3.3 阶段 2：主恢复网络（stage (c)）的微调配置 + 早停

新增 `configs/sd2_finetune.yaml`（不改动现有两份配置），关键差异：

| 项 | 现状 | 建议 | 依据 |
|---|---|---|---|
| 起点 | `g_pretrain_path=HYPIR_sd2.pth` | 不变（继续微调） | 对齐 2 |
| `batch_size` | 2 | 云端 4\~6（先做 batch 扫描）；本机 8 GB 仅冒烟 | P5 |
| `gradient_accumulation_steps` | 1 | 2（等效 batch 8） | 小 batch 的 GAN 梯度噪声 |
| `lr_G` / `lr_D` | 6e-6 常数 | 峰值 **2e-6\~3e-6**，warmup 100 步 → cosine 退火到 5% | P4 |
| `lr_scheduler` | 无 | `cosine`（**命名避开 `self.scheduler`**） | P4/P6 |
| `opt_kwargs` | `{betas}`（隐式 wd=0.01） | `{betas:[0.9,0.999], weight_decay: 0.0}` | P4 |
| `max_train_steps` | 30000/40000 | **15000（安全上限）**，实际停止交给早停 | P4 |
| 验证 | 无 | 新增 `data_config.val`：按**源图**留出 512 张源图（≈1200 tile），评估时固定取 128 张；`base_seed` 固定 | 见下 |
| 早停 | 无 | `monitor: val/lpips`(min)、`patience: 8`、`min_delta: 5e-4`、`min_steps: 600`、`eval_steps: 200`；**step 0 先评估官方权重作为初始 best** | P4 |
| 存盘 | 每 500 步全量 | 轻量 `best/`（LoRA + EMA ≈ 2 GB）+ 全量 `checkpoint-*` 拉长到每 4 个 eval 点 | P6 |
| `set_epoch` | 未调用 | 在 epoch 边界调用 | P6 |

**验证集设计要点**：

1. **按源图留出**：`Data/merged_512.zip` 内 `tiles.csv`（`id,dataset,src_path,...`）给出 157,591 个 tile ← 68,441 张源图（≈2.3 tile/图）。按 tile 随机留出会**同源泄漏**，必须按 `src_path` 分组留出。
2. **口径选择**：in-loop 用**训练口径**（单张 512 直通，快、与 LoRA 目标一致）；**部署口径**（tiled + `wavelet_reconstruction`）由独立脚本 `tools/eval_checkpoint.py` 在里程碑上跑。两者必须都做，避免"训练口径选出的点部署后反而更差"。
3. **指标网络要记清**：trainer 用 `net_lpips=vgg`（`base.py:132`），`evaluate_tool` 默认 `alex` —— **两套数值不可混比**。
4. **最终选点**：赛题验证集 5 对（`Data/competition/evaluate`）**永远不参与训练**，只用于里程碑与最终选点复核。

**验收标准**：`best/state_dict.pth` 能被 `SD2Enhancer` 直接加载；在部署口径下，5 对验证集的 PSNR/SSIM/LPIPS **不差于 step 0 基线**（若全程未超过基线，则保留原始权重——这本身就是有价值的结果）。

### 3.4 阶段 3：赛题域的退化合成适配

`doc/初步分析.md` §5 已列清单，本文补充与训练链路的衔接：

1. `SceneDegradation` 已实现运动模糊/逆 ISP/forward ISP/眩光/JPEG（`configs/degradation_baseline.yaml`），**必须与 stage (b) 用同一份 cfg**，否则 encoder 学到的 pre-removal 与 stage (c) 的观测分布不一致。
2. **合成分布校验器**（`doc/初步分析.md` §9 待办）应升级为**训练前置关卡**：合成 LQ 的指纹（残差 RMS / 高频占比 / 平坦残差 / 偏色量）必须覆盖验证集 5 个真实点。覆盖不到的成分（当前重点是偏色），微调补不上。
3. 数据侧注意：训练集 68,441 张源图中**没有钟表类图片**，而赛题场景含钟表（域 gap，决策见 §4）。

## 4. 决策与风险

### 已决策

| 事项 | 决策 |
|---|---|
| 训练起点 | 从 `HYPIR_sd2.pth` 继续微调（不从头训） |
| 训练顺序 | **按论文：先 (b) encoder → 冻结 → (c) 主网络**；先做阶段 0 判定是否已有官方 (b) 产物 |
| VAE encoder 在 (c) 中的角色 | **固定输入管线组件**，不出现在 (c) 的可训参数中 |
| 阶段 0 的实现约束 | 所有新开关默认关闭/保持现状，不改变既有链路行为 |
| 早停验证集 | 合成留出集（按源图留出，128 张 512）+ in-loop 训练口径 |
| 早停监控 | `val/lpips`(min) 为主，PSNR/SSIM 作护栏 |
| 正式训练硬件 | 云端 24 GB；本机 8 GB 仅做冒烟 |
| 验证集隔离 | 赛题 5 对不参与训练，仅用于选点与评估 |

### 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **0-A 假设不成立** | `sd2_denoise_ae_encoder.pth` 可能不对应 `HYPIR_sd2.pth`（例如属于其他变体） | 0-A 有明确判定标准；不成立则转入自行实现 stage (b) |
| **stage (b) 的目标函数退化** | 论文 `L_E` 存在"encoder → 常数"的平凡最优 | 加 `λ_keep·重建` 护栏 + 小 LR/少步数 + 早停 |
| **验证集是合成代理** | in-loop 指标衡量"反演我们自己的退化管线"，未必等于赛题真实 LQ | 里程碑用真实 5 对 + `evaluate_tool` 复核 |
| **域迁移震荡** | 从官方权重切到场景退化，前数百步指标可能先变差 | 早停设 `min_steps: 600`；step 0 基线保证可回退 |
| **钟表域 gap** | 训练集无钟表图 | 先用现有数据训，效果不足再补（二阶段决策） |
| **单步耗时不详** | `SceneDegradation` 的 CPU 开销未实测（`doc/初步分析.md` §9/§12） | 正式训练前先跑 100\~200 步测 `s/step`，再定 `eval_steps` 与步数上限 |

### 待确认

- [ ] `sd2_denoise_ae_encoder.pth` 的确切来源与配套权重（0-A 实验可判定；官方 README 只列了 `HYPIR_sd2.pth`）
- [ ] 论文 §5.3 的 stage (b) 具体超参（LR/步数/batch）——arXiv HTML 在本地抓取时被截断，需人工核对原文
- [ ] `wavelet_reconstruction` 在同尺寸恢复下是保留、关闭，还是改为可调权重（依赖 0-B2 结果）

## 6. 建议的执行顺序（一页速览）

```
阶段 0（不训练，<1.5h）
  ├─ 0-A  encoder 往返重建判定        → 决定是否已有官方 (b) 产物
  └─ 0-B  wavelet / sample / tiling / (model_t,coeff_t) A/B  → 定位基线症状的最小修复集

阶段 1（仅当 0-A 判定需要）
  └─ 论文 stage (b)：只训 encoder（decoder 冻结，L_E + 重建护栏）
     → 产物 HYPIR_sd2_encoder.pth（独立 artifact）→ 纳入推理契约

阶段 2（stage (c) 微调）
  ├─ 测步速 → 云端 batch 扫描 → 生成 val_names.json
  ├─ 新配置 sd2_finetune.yaml（低 LR + 退火 + 验证 + 早停 + best/）
  └─ 早停后：tools/eval_checkpoint.py 在真实 5 对上做部署口径定选

阶段 3
  └─ 合成分布校验器作为训练前置关卡；赛题域退化适配与 (b)(c) 域一致
```
